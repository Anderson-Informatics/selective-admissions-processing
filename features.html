EHS Admissions Automation — Product Features

This document lists the core product features derived from the technical specification. The features are ordered in a sensible implementation sequence.

1. Login

Staff sign in to access the application. The initial release uses a simple email and password list stored in environment configuration; this will later be replaced with single sign-on once the Azure app is configured.

User Flow

  1. Open the application.
  2. Enter an authorized email and password.
  3. Click Sign In.
  4. Land on the dashboard.

UI Overview

  • Email and password inputs.
  • Sign In button.
  • Error message for invalid credentials.

2. Cycle Management

Create and manage admissions cycles. A new cycle can be bootstrapped by cloning the previous year so most settings carry forward.

User Flow

  1. Open the Cycles page.
  2. Click New Cycle or Clone Previous Cycle.
  3. Set the year, date ranges, and scoring weights.
  4. Activate the cycle.

UI Overview

  • Cycle list with status (active/inactive).
  • Clone and edit buttons.
  • Cycle editor form.

3. School & Review Stage Configuration

Map each school and its review pipeline to the corresponding projects and stages in Submittable for the active cycle.

User Flow

  1. Select the active cycle.
  2. View imported projects and stages.
  3. Map each school to its project and each review stage to its stage name.
  4. Save the configuration.

UI Overview

  • School list with project mappings.
  • Review stage mapping table.
  • Searchable selects and save controls.

4. Form Import & Field Mapping

Import form schemas from Submittable and map each form field label to a canonical application field. New or changed fields are flagged so staff can map them before extraction runs.

User Flow

  1. Open the Form Definitions page.
  2. Import or refresh a form.
  3. Review the list of fields.
  4. Map each label to a canonical field name.
  5. Resolve any unmapped-field warnings and save.

UI Overview

  • Form list with import/refresh actions.
  • Field mapping table.
  • Unmapped-field alert banner.
  • Save and cancel buttons.

5. Job Runner

A central place to trigger, monitor, and re-run every processing job. Each job reports its status, progress, and logs.

User Flow

  1. Go to the Jobs page.
  2. Select a job type and the target cycle.
  3. Configure any optional scope (schools, forms).
  4. Click Run and watch the status update.
  5. View logs and re-run if needed.

UI Overview

  • Job list with status badges.
  • Progress bars and record counts.
  • Run and re-run buttons.
  • Expandable log viewer.

6. Data Extraction

Sync metadata and pull application submissions from Submittable into the app, then normalize form responses using the stored field mappings.

User Flow

  1. Run Metadata Sync to refresh projects, forms, labels, users, and stages.
  2. Run Submission Extraction for the active cycle and selected schools.
  3. Run Form Response Mapping to apply field mappings.
  4. Confirm record counts and completion status.

UI Overview

  • Cycle and school selectors.
  • Extraction job panel with progress indicators.
  • Record count summaries.

7. Data Summary Dashboard

A high-level overview of the active admissions cycle, showing key metrics and completion rates across schools and review stages.

User Flow

  1. Open the Dashboard.
  2. Select the active cycle.
  3. Review summary cards and tables.
  4. Click any metric to drill into the relevant list.

UI Overview

  • Summary cards for applications, issues, reviews, exams, and scoring.
  • Data tables with sorting and filtering.
  • Cycle selector and filter bar.

8. Submission Detail View

Inspect a single applicant's complete record: raw and normalized form data, labels, validation issues, scores, and routing history. A direct link opens the submission in Submittable for review.

User Flow

  1. Click a submission from the dashboard or issue list.
  2. Review the detail tabs.
  3. Click Open in Submittable to review or correct the record there.

UI Overview

  • Detail page or slide-over panel.
  • Tabs for fields, issues, scores, and history.
  • External link to Submittable.

9. Validation & Issue Triage

Run configurable validation rules to detect data-quality problems such as out-of-range dates of birth, bad student numbers, duplicate applicants, missing documents, label mismatches, incomplete review stages, and geocoding failures. Staff can review each issue and jump to Submittable to fix it.

User Flow

  1. Run Validation for the active cycle.
  2. Open the Validation Issues page.
  3. Filter by school, stage, severity, or issue type.
  4. Click an issue to view the submission detail.
  5. Open the record in Submittable and resolve the underlying problem.

UI Overview

  • Validation job trigger.
  • Issue table with filters and severity badges.
  • Issue detail panel.
  • Open in Submittable link.

10. Routing Automation

Automatically move Application-HS and DSA submissions to the appropriate review stage based on completion scores, decision scores, or audition outcomes.

User Flow

  1. Run the Application-HS Routing job for the active cycle.
  2. Run the DSA Audition Compilation & Routing job.
  3. Review the summary of stage changes.
  4. Investigate any submissions that could not be routed.

UI Overview

  • Routing job triggers for App-HS and DSA.
  • Stage-change summary table.
  • Routing log viewer.

11. HSPT Upload & Matching

Upload raw HSPT results from STS, match each test record to the correct application by ID code, and resolve any remaining records with fuzzy name/DOB matching or manual linking.

User Flow

  1. Open the HSPT Upload page and select the cycle/test administration.
  2. Upload one or more raw STS CSV files.
  3. Wait for the system to parse the files and compute scaled scores.
  4. Review the match review table: records matched by OptCd, fuzzy candidates, and unmatched rows.
  5. For each fuzzy or unmatched record, compare the HSPT and application data, then accept or reject the suggested match.
  6. Use the HSPT Results page to search by name or date of birth and manually link any unmatched record to an unlinked submission.

UI Overview

  • File upload control for raw STS CSVs.
  • Match review table with HSPT data, candidate application data, match score, match type, and Accept/Reject actions.
  • Filters for matched, fuzzy, unmatched, and manually linked records.
  • HSPT Results search page with name/DOB search and linked status.
  • "Link application" button opening a searchable dropdown of unlinked submissions by full name.

12. GPA Data Ingestion

Bring in GPA data from two outside sources — district GPA records sent to the app by the DPSCD data feed, and XLSX files returned by out-of-district opt-in schools — so a student's cumulative GPA is available for scoring even when it was never recorded on a review form.

User Flow

  1. DPSCD GPA records are pushed to the app automatically; staff watch the import job on the Jobs page and review matched/unmatched counts.
  2. Open the GPA page and select the cycle.
  3. Upload one or more Opt-In school XLSX files.
  4. Review the preview table: matched students, warnings for rows missing the Opt-In label, and any unmatched rows.
  5. Confirm the import — only students included in the files are updated.
  6. See the imported GPA records listed on the GPA page.

UI Overview

  • GPA page with cycle selector and Opt-In file upload.
  • Preview table showing each file row's match and label status before anything is saved.
  • Imported GPA records table showing student, school, cumulative GPA, and enrollment terms.
  • Job log entries with matched/unmatched counts for both imports.

13. Score Compilation

Combine exam, GPA, essay, and bonus scores into total application scores, then write the computed scores back to the internal forms in Submittable. Percentile ranks for total, GPA, essay, and exam scores are also computed.

User Flow

  1. Run the Score Compilation job after reviews, exams, and GPA data are recorded.
  2. Review the computed totals and percentiles for accuracy.
  3. Run Update Submittable Internal Forms to push scores back.
  4. Confirm the write-back summary.

UI Overview

  • Score compilation job trigger.
  • Score summary table with total score cards.
  • Percentile columns for application and exam components.
  • Write-back status and confirmation.

14. Catchment & Address Lookup

Geocode applicant addresses and determine catchment status for relevant schools so bonuses and assignments can be applied correctly.

User Flow

  1. Run the Catchment job for the active cycle or a single submission.
  2. View the catchment result on the submission.

UI Overview

  • Catchment status badge on submission detail.
  • Catchment job trigger and summary.

15. Roster Upload

Update the lookup-tool rosters used by exam and application staff with the current set of applicants, exam registrations, and accommodations.

User Flow

  1. Run the Roster Upload job for the active cycle.
  2. Review the record counts and confirmation.

UI Overview

  • Roster upload job trigger.
  • Record count summary and status.

16. CSV Export

Download any visible dataset as a CSV for use in external tools, reports, or downstream processes.

User Flow

  1. Navigate to a table (submissions, issues, jobs, scores, placements).
  2. Apply desired filters.
  3. Click Export CSV.
  4. Download the file.

UI Overview

  • Export button on tables and lists.
  • Filter bar controlling exported rows.
  • Download notification or dialog.

17. Placement Scenarios

Run the school-assignment algorithm using ranked applicant choices, total scores, and user-defined capacity and cut-score values. Staff can create multiple scenarios, compare summary results, and export final placement lists.

User Flow

  1. Open the Placement Scenarios page.
  2. Create a new scenario and name it.
  3. Enter the capacity and cut score for each school (and optional minimum GPA/exam thresholds).
  4. Run the placement job against the compiled scoring file.
  5. Review the per-school summary and the individual assignments.
  6. Adjust inputs and re-run, or export the scenario results.

UI Overview

  • Scenario list with active/finalized status.
  • Capacity and cut-score input form per school.
  • Placement summary table showing seats, cut scores, placed counts, and choice distribution.
  • Individual placement table with assigned school and choice rank.
  • Export buttons for placement list and summary.

18. Placement Results & Percentiles

Generate percentile-based results summaries for placed and unplaced applicants, and prepare communications that explain how an applicant scored relative to the overall pool. Results are sent through Submittable.

User Flow

  1. Select a finalized placement scenario.
  2. Generate the percentile report for total score, GPA, essay, exam, and exam subcomponents.
  3. Preview the applicant-facing results message.
  4. Send the messages through Submittable.

UI Overview

  • Percentile report preview.
  • Message preview panel with merge fields.
  • Send confirmation and status summary.
