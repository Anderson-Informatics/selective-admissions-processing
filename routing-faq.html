EHS Admissions Automation — Routing FAQ

Technical Specification Product Features Jobs Specification

This document records the routing concepts and decisions that guide the configuration-driven routing system. It is intended to clarify the business meaning of routing configuration before automated Submittable writes are enabled.

What is an Entry Action?

An Entry Action is an automatic side effect that occurs when a submission is routed into a stage.

Possible entry actions include:

  • assigning one or more reviewers;
  • removing reviewers;
  • adding a Submittable label; and
  • removing a Submittable label.

For example, entering a GPA stage could assign an out-of-district reviewer:

{
  "when": {
    "all": [
      {
        "kind": "label",
        "op": "hasLabel",
        "labelId": "<upload-required-label>"
      }
    ]
  },
  "assignUserIds": ["<Thomas Cairgle userId>"],
  "unassignUserIds": ["<Nicholas Hanson userId>"]
}

Entry actions are different from status labels:

  • statusLabels synchronizes a calculated stage status such as Needs One Review to a Submittable label.
  • entryActions performs an action when the submission enters the stage.
Essay Scoring decision: Essay Scoring has no entry actions. The legacy process calculates essay review status and synchronizes essay status labels, but it does not automatically assign a reviewer or perform another side effect when a submission enters Essay Scoring.

What is the reviewCompletion ledger?

Each submission receives one ledger entry for every configured review stage: 

{
  "stageId": "<stage-id>",
  "name": "Essay Scoring",
  "order": 30,
  "role": "work",
  "required": true,
  "status": "Needs One Review",
  "complete": false
}

The ledger is a materialized view of the submission's current routing state. It is recalculated from mapped fields, labels, reviews, GPA records, HSPT links, and stage configuration. It is not the source of truth for the raw application or review data.

How is the next stage selected?

Routing eventually follows this sequence:

  1. recalculate the submission's reviewCompletion ledger;
  2. apply a matching outcome override, such as Decision Review → Declined;
  3. otherwise find the lowest-order stage where required is true and complete is false;
  4. only propose a move when the target stage's routing configuration is enabled; and
  5. flag a move to a lower-order stage as a backward-routing warning.

Draft or disabled routing configuration can still calculate useful ledger values for reporting, but it cannot cause an automated move.

What are the stage roles?

  • Initial — the entry stage, such as New Application.
  • Work — a normal review or processing stage.
  • Hold — a valid waiting state, such as GPA Pending or NO EXAM.
  • Final — an outcome stage that ordinary next-stage routing does not select.

How is New Application completed?

New Application is complete once the initial form has been extracted and mapped. The current implementation uses Submission.isMapped as the completion signal.

The intended statuses are:

  • Mapped — complete;
  • Awaiting Initial Mapping — incomplete.

Once New Application is mapped, routing immediately evaluates the next required incomplete stage. New Application has no entry actions or outcome rules.

How does Essay Scoring status work?

Essay Scoring is required for every EHS 9th Grade submission.

  • zero reviews → Needs Two Reviews;
  • one review → Needs One Review;
  • exactly two reviews with score spread at least 6 → Needs Third Review;
  • two reviews with spread below 6 → Essay Scoring Complete; and
  • three or more reviews → Essay Scoring Complete, regardless of spread.

These statuses may be synchronized to the corresponding Submittable essay labels. No reviewer assignment or other Entry Action is required.

How do draft templates work?

Templates use symbolic stage names rather than hard-coded stageIds. When a template is applied, the application resolves those names against the selected project's actual stages.

Draft templates, including the current EHS templates, are persisted with routing disabled. Their ledger conditions can still be inspected and tested, but they cannot initiate automated moves until the configuration is reviewed and enabled.

A missing stage reference is reported as a warning and must be corrected before relying on the template for routing decisions.

What is the difference between preview and execution?

The routing preview evaluates the current data and configuration without changing Submittable or the submission records. It shows proposed moves, ledger details, diagnostics, and backward-routing warnings.

Execution will be a separate confirmation workflow. It will eventually use persisted RoutingRun records, allow individual submissions to be excluded, recheck stale stages, and only then perform Submittable writes.
